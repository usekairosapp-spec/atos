# Story FND-001 — Fundação técnica, autenticação e isolamento multi-igreja

## Status

Ready for Development

## História

Como administradora da plataforma, quero uma base web conectada ao Supabase, com autenticação e isolamento por igreja, para que as próximas funcionalidades sejam construídas com segurança.

## Rastreabilidade

FR-001 a FR-007, FR-020; NFR-001 a NFR-004, NFR-007 a NFR-010; BR-001 a BR-004.

## Critérios de aceite

- [x] Visitante cria conta e recebe perfil correspondente no Supabase.
- [x] Login, logout, recuperação de senha e rota autenticada estão implementados.
- [ ] Usuário recebe apenas registros das igrejas às quais está vinculado.
- [ ] Acesso direto a outra igreja é bloqueado por RLS.
- [ ] Administradora atribui um membro como líder de um setor.
- [ ] Líder não administra setor sem atribuição.
- [x] O modelo permite voluntário em vários setores sem duplicar a conta.
- [x] Toda nova igreja recebe Técnica, Mídia, Oficiais, Louvor, Recepção e Kids.
- [ ] Segredos de servidor não são versionados nem enviados ao cliente.
- [ ] README permite executar uma instalação limpa.
- [x] Lint, verificação de tipos, testes e build passam.
- [ ] Login e layout base funcionam em 360 px e desktop.

## Tarefas

- [x] Criar aplicação Next.js com TypeScript e Tailwind.
- [x] Configurar cliente e servidor Supabase por variáveis de ambiente.
- [x] Criar cadastro, login, logout e recuperação de senha.
- [x] Criar layout autenticado e proteção de rotas.
- [x] Criar primeira migration com perfis, igrejas, setores, vínculos e papéis.
- [ ] Aplicar e validar policies RLS no projeto Supabase conectado.
- [x] Criar seed automático dos seis setores iniciais.
- [x] Criar interface base responsiva seguindo `docs/ux/flows.md`.
- [x] Documentar requisitos, arquitetura e fluxos iniciais.
- [x] Executar quality gates.
